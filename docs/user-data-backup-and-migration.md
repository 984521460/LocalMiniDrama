# 用户数据备份、恢复与迁移

本文是 Windows 桌面版用户数据的权威操作说明。安装版和便携版使用同一套用户数据目录；便携版不会把项目数据保存在 EXE 旁边。

## 1. 数据位置

当前稳定目录：

```text
%APPDATA%\localminidrama-desktop
```

旧版目录：

```text
%APPDATA%\LocalMiniDrama
```

稳定目录中的主要内容：

| 路径 | 内容 | 备份建议 |
|---|---|---|
| `backend\data\drama_generator.db` | SQLite 项目、工作流和生成记录 | 必须 |
| `backend\data\storage` | 本地图片、视频、音频和成片 | 必须 |
| `backend\configs\config.yaml` | 本地服务、存储和 Provider 配置 | 建议；按敏感资料保护 |
| `backend\logs`、`main-startup.log` | 诊断日志 | 可选 |
| `backend\tools\ffmpeg` | 可重新安装的本地工具 | 可选 |

项目 ZIP 适合迁移单个项目，但不是完整用户数据备份：它不代替全局配置、所有项目、日志和 Windows 凭据存储。

## 2. 创建完整备份

1. 在应用内等待正在写入、导入、导出或生成的任务结束。
2. 完全退出 AI漫剧工作台，并确认安装版或便携版进程已经结束。
3. 将整个 `%APPDATA%\localminidrama-desktop` 目录复制到另一个受保护的位置。不要只复制数据库文件，也不要在应用运行时复制。
4. 对备份至少核对目录总大小和文件数量；重要备份应由备份工具生成并核对文件哈希。
5. 保留原备份，先在隔离目录或新机器上验证可以启动、打开项目并访问媒体，再决定是否清理旧副本。

必须停机复制，因为 SQLite 使用 WAL，媒体文件也可能仍在写入。运行中只复制 `drama_generator.db` 或只复制 `storage`，可能得到数据库与媒体不一致的快照。

数据库、配置文件和历史日志可能含旧版 AI 服务 API Key、本机路径、服务地址或其他敏感配置。备份应加密或放在受控磁盘中，不要上传到公开网盘、Issue、聊天或代码仓库；备份一旦失去控制，应轮换其中可能包含的凭据。

## 3. 在同一台电脑恢复

1. 完全退出应用。
2. 如果 `%APPDATA%\localminidrama-desktop` 已存在且非空，先将其整体改名为一个恢复前副本；不要把两棵目录直接合并。
3. 将已验证的完整备份复制为 `%APPDATA%\localminidrama-desktop`。
4. 启动应用，检查项目数量、关键项目、媒体和配置。
5. 验证完成前保留恢复前副本。若恢复失败，退出应用，移走失败目录，再把恢复前副本改回稳定目录。

不要把安装目录、便携版 EXE 所在目录或 `%LOCALAPPDATA%` 当成用户数据恢复目标。

## 4. 迁移到新电脑

1. 在旧电脑按第 2 节创建并验证完整备份。
2. 在新电脑安装相同或更新版本，但首次启动前不要创建或编辑项目。
3. 完全退出新电脑上的应用，将备份复制到 `%APPDATA%\localminidrama-desktop`；若该目录已非空，先整体改名保留，不要合并。
4. 启动并核对项目、媒体和配置。
5. 在 AI 配置或连接设置中重新配置凭据。

采用 `credential:v1:<UUID>` 的新连接只在数据库保存引用，其秘密保存在 Windows Credential Manager，不在普通文件备份或项目 ZIP 中；跨 Windows 用户或跨电脑迁移后必须重新配置这些凭据。旧版 AI 服务 API Key 可能仍位于 SQLite 数据库中并随完整备份复制，因此整个备份都应按秘密资料保护。不要导出、复制或记录凭据原值。

## 5. 从旧版目录升级

首次启动新版时，应用会在创建新日志前尝试把 `%APPDATA%\LocalMiniDrama` 整体重命名为 `%APPDATA%\localminidrama-desktop`：

- 稳定目录不存在或为空：迁移旧目录；
- 稳定目录已经包含数据：使用稳定目录，不覆盖旧目录；
- 删除空稳定目录或重命名失败：本次继续使用旧目录，并在后续启动重试。

升级前仍应先备份旧目录。若稳定目录和旧目录都非空，不要手工合并数据库或媒体；保留两者，确认哪一套是当前有效数据后再处理。卸载程序默认保留用户数据，但“卸载不删除”不等于已经备份。

## 6. 自动数据库迁移安全副本

旧数据库首次进入 v2 迁移前，后端会在数据库旁创建并验证：

```text
backend\data\drama_generator.db.pre-v2.sqlite
backend\data\drama_generator.db.pre-v2.manifest.json
```

Manifest 记录副本文件名、大小、SHA-256、完整性结果和 generation ID。该机制只保护迁移前的 SQLite 数据库，不包含 `storage` 媒体、配置、凭据或其他用户数据，因此不能替代第 2 节的完整外部备份。

如果启动报告 `V2_MIGRATION_BACKUP_INVALID`，停止反复启动或删除这些文件；保留数据库、副本和 Manifest，使用完整备份恢复或交给维护者分析。不要把 pre-v2 数据库直接覆盖到已经运行新 Schema 的目录。

## 7. 最小验收清单

- 应用已完全退出；
- 备份源是 `%APPDATA%\localminidrama-desktop`，不是安装目录；
- 数据库、`storage` 和配置均在备份中；
- 恢复时没有合并两个非空用户数据目录；
- 新电脑上的凭据已单独重新配置；
- 至少打开一个项目并验证关键媒体可用；
- 验证完成前保留旧目录和原始备份。
